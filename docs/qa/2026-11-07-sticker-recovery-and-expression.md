# 表情输入中断恢复与颜文字多样性

## 观察到的问题

本地日志显示，GIF 粘贴后、点击发送前，编辑焦点或键鼠输入发生变化，原流程将整个会话暂停。预览核对失败也会触发同类暂停。图片留在输入框不代表发送成功。

模块化人格的语言后处理为了保留表达强度跳过了风格配额，但也没有针对同一个颜文字的重复检查；原候选仅 6 个。

## 调整

- 数据库接收继续进行。只对同一进程内、尚未点击发送的表情事务保留恢复资格，等待空闲；不重复粘贴。
- 恢复时重新核对账号、目标标题、输入焦点和整个输入区。要求完整原图预览，并拒绝额外文字、第二张图、滚动条或裁切预览；不以非空输入框作为成功依据。
- 人工清空、过期、暂停与未知发送不补发。重启不复活旧草稿。真正点击发送后仍用对应会话的数据库回执确认。
- 13 类、208 个颜文字参考覆盖软萌、开心、得意、害羞、安慰、委屈、惊讶、疑惑、调皮、小脾气、困倦、招呼和期待。
- 生成前给出该会话近期用过的候选及同情绪替代；生成后对重复的已知画法作同类替换。候选由本地确定性选择完成，不增加模型请求。
- 不强行给纯文字追加颜文字，不把委屈替换成大笑，不改动引用、代码、路径或逐字输出。只统计本会话助手的文字，不统计群友或已知未发出的内容；没有跨会话使用记录。
- 自定义人格可追加 `xiaomao.kaomoji.persona_reference()` 的完整参考文本，原有内容不删减。运行时的少量候选提示不要求模型机械轮流使用清单。

## 自动化验证与实际范围

`tests/test_sticker_interruption.py` 覆盖中断后继续接收、原草稿只发送一次、人工修改、清空、过期、人工暂停、换号、切错聊天、未知回执，以及完整预览之外的文字、第二张图和滚动条。

`tests/test_kaomoji_variety.py` 覆盖候选数量与唯一性、每种情绪连续表达不重复、同气泡去重、空格变体、引用和路径保护、已知未发出文本不计入历史，以及不把聊天内容提升为生成规则。

测试使用本地合成界面和模拟传输，不向真实联系人发送测试消息。本次中断恢复改动没有额外发送真实群聊消息；既有 README 微信截图是注明日期的历史实测，不作为本次新恢复分支的实机发送证明。

发送依然需要可交互的微信窗口。用户操作、隐藏桌面、无法证明草稿内容等情况会等待；此修复不承诺持续无焦点切换，也不保证账号不会受平台风控影响。
