# 微信原生语音实施计划

> 使用 superpowers:executing-plans 逐项实施。原生语音在用户指定的本机测试会话验证后，进入 Fabric 与音色界面集成。

**目标** 在拾光中通过微信原生录音发出可播放的语音气泡。

**基线** GitHub v0.3.20，提交 `02b995a3c919ff6d6f670cf262de0e107ead0a30`。

**架构** Python 后台负责音频和微信发送，Electron 提供设置及诊断入口。渲染到选定的虚拟音频输出，微信从对应虚拟输入录制。生成音频不占用微信窗口。实际录音复用现有的窗口身份检查与发送协调。

## 全局约束

- 先以本地测试音频走通当前账号的指定测试会话，再对接 Fabric。微信支持条件以实际录音控件及回放校验为准。
- 测试入口使用本机保存的指定会话。正式语音按账号、会话和用户配置授权。
- 音频输出使用稳定的 Windows 端点 ID。设备消失或无法确认时结束当前尝试。
- 录音取消及提交后的未知结果要与已确认送达区分。发送结果未知时不自动重发。
- 公开发布按需从软件内下载运行环境和模型。沿用 Fabric 的角色包、参考音频及参数能力，并保留上游许可和署名。

## 复核重点

- WAV 损坏、内容被截断或超过语音长度限制。
- 声卡重新枚举、设备断开、取消播放以及长音频的输出超时。
- 录音期间切换焦点、会话或账号，微信语音入口缺失，原有草稿受保护。
- 点击提交或释放录音按钮后回执丢失，保护原任务免于重复发送。
- 更换显卡、音色或模型路径，已有账号数据与已下载模型可正常恢复。

## 任务 2 · 原生语音气泡实测

- [x] 更新后的客户端上检查原生录音、取消、提交和回放状态。
- [x] 以实测的控件行为实现录音发送及指定会话的测试入口。提交前保存基线，等待独立回执。实机核对了新语音气泡和实际播放。
- [x] 自动测试覆盖旧客户端、前台或输入变化、现有草稿、设备异常、成功回执和提交后失联。
- [x] 在用户指定的本机会话完成一次可播放的语音气泡验证，记录微信版本、音频路径和结果。

2026-11-22 重启后，VB-CABLE 回路复测通过。微信内置更新完成后，实际客户端版本为 4.2.0.13。用原生录音控件发送一条 8 秒气泡。Windows Core Audio 确认微信录制会话使用 CABLE Output，点播后在扬声器回环中匹配到完整测试音。固定测试会话保存在本机隔离测试配置中。

同日，录音适配在 125% DPI 的微信主窗口中完成可取消录音实测。接入 Fabric 后，社区角色经 RTX 5070 的 NVIDIA CUDA 环境生成 3.08 秒、48 kHz 单声道 WAV。发送适配保存提交标记后只点击一次，指定测试会话出现 5 秒语音气泡。点播后的扬声器回环音频与合成原音做归一化匹配，峰值为 0.581。数据库回执用合成消息库验证去重、发送方向、服务端编号和时长校验。

随后在新版微信主窗口一起复核标题、消息区、输入区、发送按钮和语音按钮。使用通道验证后的校准发送社区角色花冈柚子（中文）的试听，指定测试会话出现 8 秒语音气泡。点播后扬声器回环匹配到合成原音，峰值为 0.872。
